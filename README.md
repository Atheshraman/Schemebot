# SchemeMatch

## Project Abstract

SchemeMatch is a multilingual government-scheme discovery and eligibility assistant. Users describe their situation through a conversational AI chat interface or fill in a structured profile editor. The backend retrieves relevant schemes from a Supabase vector database, evaluates eligibility criteria with deterministic rules, and presents rich result cards with official links, benefit details, and optional YouTube explainer videos.

The project combines conversational AI (LM Studio reasoning model), semantic vector search, deterministic eligibility verification, persistent user profiles, chat history, bookmarks, voice interaction, and optional browser deadline notifications. Eligibility decisions are fully explainable and profile data remains local.

---

## Objectives

- Collect only the profile information needed to evaluate scheme criteria.
- Retrieve relevant government schemes using semantic vector search.
- Verify eligibility with transparent numeric, boolean, exact, and fuzzy rules.
- Support English, Tamil, Malayalam, and Kannada interface and assistant responses.
- Display eligible schemes as rich cards with descriptions, benefits, application links, and YouTube videos.
- Let users save profiles, conversations, and bookmarked schemes for later access.
- Keep sessions locally in the browser without requiring phone numbers or OTP.
- Notify users in the browser when a bookmarked deadline is approaching.

## Main Features

### Conversational Eligibility Assistant

- Chat interface powered by a local LM Studio reasoning model (e.g., Qwen3).
- The model thinks before responding — `<think>` blocks are generated internally and automatically stripped before showing the reply to the user.
- Required eligibility fields collected: age, gender, state, caste category, annual income, and occupation.
- The assistant asks one focused question at a time and detects when the profile is complete.
- Auto-detects the loaded model from LM Studio's `/v1/models` endpoint — no need to keep `.env` in sync manually.
- Graceful fallback message shown in the chat UI if LM Studio is offline, instead of a blank error.

### Rich Eligibility Result Cards

- Only **eligible** schemes are shown as cards after checking eligibility.
- Each card includes:
  - Scheme name with an **Eligible** badge
  - Full description of the scheme
  - Benefits section (what the user receives)
  - Official **Apply Now** button linking to the application URL
  - **View on MyScheme** button linking to the source page
  - Embedded **YouTube video thumbnail** with click-to-play — shows a video explainer if available
- A conversational summary bubble also recaps how many schemes were found, how many need more info, and how many were not eligible.
- Cards animate in with a staggered entrance effect.

### Scheme Scraper (myScheme.gov.in)

- Discovers schemes via SerpAPI (`site:myscheme.gov.in/schemes` search).
- **Multi-strategy extraction** handles myScheme's Next.js SPA architecture:
  1. **SerpAPI rich snippets** — extracts description, benefits, and apply links from search result metadata (most reliable)
  2. **`__NEXT_DATA__` JSON** — parses Next.js SSR props embedded in the page shell
  3. **JSON-LD structured data** — extracts schema.org `description` and `provider`
  4. **Open Graph / meta tags** — always available even in SPA shells
  5. **Heuristic heading search** — finds nearby paragraph text under "Benefits", "Eligibility", etc.
- `_upsert_scheme()` only overwrites Supabase fields where the new value is **non-empty** — existing good data is never erased by a failed scrape.
- `_upsert_criteria()` deletes old eligibility criteria before re-inserting — no duplicate rows on re-scrape.
- Per-scheme field diagnostics logged: shows exactly which fields populated and which are empty.
- YouTube video URL is looked up via SerpAPI and stored in the `youtube_url` column.

### Search and Verification

- Embeddings generated by `all-MiniLM-L6-v2` (sentence-transformers) stored in Supabase with `pgvector`.
- `match_schemes` Supabase RPC retrieves top candidate schemes by cosine similarity.
- Deterministic verifier supports:
  - Numeric comparisons (`less_than`, `greater_than`, `lte`, `gte`)
  - Boolean fields (`bpl_status`, `disability`, `has_bank_account`, etc.)
  - Exact equality and fuzzy text matching (via `SequenceMatcher`)
  - List membership (`in`, `one_of`)
- Eligibility result per scheme: `eligible`, `needs_more_info`, or `not_eligible` with a human-readable reason.

### Account and Persistence

- Profile data stored in local SQLite `profile.db` — no external auth needed.
- Browser keeps session ID in `localStorage` so the user returns to the same profile.
- `GET /profile/{session_id}` **auto-creates** a new empty profile for new sessions instead of returning 404.
- Chat messages stored and viewable through the Chat History tab.
- Bookmarked schemes stored per session with optional deadline.

### Bookmarks and Reminders

- Eligible scheme cards can be bookmarked or unbookmarked with one click.
- Bookmarks may contain a scheme deadline date.
- Browser checks bookmarked deadlines every five minutes while the app is active.
- Browser Notification API shows an alert when a deadline is within seven days.

### User Experience

- Responsive browser UI for desktop and mobile.
- Live language switching (English, Tamil, Malayalam, Kannada) without refreshing.
- Browser speech input and assistant text-to-speech readback.
- Speech sanitization removes emojis, URLs, markdown, and special characters before reading aloud.
- Light and dark themes.
- Profile snapshot showing name, age, gender, and state.

## System Architecture

```text
Browser UI (index.html)
        |
        | REST requests (CORS: localhost:5173, 127.0.0.1:5173)
        v
FastAPI backend (main.py / routes.py)
        |
        +---> LM Studio (local reasoning model, auto-detected via /v1/models)
        |         Qwen3 / any OpenAI-compatible model
        |         Think block generated internally, stripped before reply
        |
        +---> SQLite (profile.db)
        |         user_profile, chat_messages, bookmarked_schemes
        |
        +---> Supabase + pgvector
        |         schemes table, eligibility_criteria table
        |         match_schemes RPC (HNSW cosine similarity index)
        |
        +---> SerpAPI
        |         Scheme discovery (site:myscheme.gov.in/schemes)
        |         YouTube video lookup per scheme
        |
        +---> Browser Notification API
                  Deadline reminders (client-side, 5-min polling)
```

## Requirements

### Local

- Windows, macOS, or Linux
- Python 3.10 or newer
- A modern browser (Chrome or Edge recommended for speech features)
- [LM Studio](https://lmstudio.ai/) with a chat-completions server running on port 1234
  - Recommended model: **Qwen3** (any size) or any OpenAI-compatible chat model
  - Set **Context Length ≥ 8192** in LM Studio model settings for reasoning models

### External Services

- Supabase project with `pgvector` extension enabled
- SerpAPI key for scheme scraping and YouTube video lookup

## Configuration

Edit `.env` with your values:

```env
# Supabase
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_KEY=your_service_role_key

# Scrape endpoint protection
ADMIN_TOKEN=long_random_secret_token

# SerpAPI (scheme discovery + YouTube lookup)
SERPAPI_KEY=your_serpapi_key

# LM Studio (local AI model)
LMSTUDIO_API_URL=http://127.0.0.1:1234/v1/chat/completions
LMSTUDIO_MODEL=qwen3.5-4b          # Must match model ID in LM Studio (auto-detected if wrong)
LMSTUDIO_TEMPERATURE=0.1           # Lower = faster, more deterministic
LMSTUDIO_DISABLE_THINKING=true     # Strips <think> tags from response (safe to leave true)
```

> **Note:** `LMSTUDIO_MODEL` is auto-detected from `/v1/models` at runtime. If it doesn't match, the backend falls back to the detected model automatically.

Never commit `.env` or expose secrets in frontend code.

## Database Setup

1. Open the Supabase SQL editor.
2. Paste and run the contents of `schema.sql`.
3. Confirm that `schemes`, `eligibility_criteria`, the HNSW embedding index, and the `match_schemes` function exist.

The local SQLite database (`profile.db`) is created automatically on first run. It stores:

| Table | Contents |
|-------|----------|
| `user_profile` | One row per session: age, gender, state, income, etc. |
| `chat_messages` | Full chat history per session |
| `bookmarked_schemes` | Bookmarked scheme IDs + deadlines per session |

## Running the Application

**Step 1 — Start LM Studio server:**
1. Open LM Studio → load a model (e.g., Qwen3 5B)
2. Go to **Server** tab → click **Start Server** (port 1234)
3. In model settings, set **Context Length to 8192** for reasoning models

**Step 2 — Start the backend:**

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

**Step 3 — Start the frontend:**

```powershell
.\.venv\Scripts\python.exe -m http.server 5173 --bind 127.0.0.1
```

**Step 4 — Open in browser:**

- Frontend: http://127.0.0.1:5173/index.html
- API docs: http://127.0.0.1:8000/docs

## API Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/chat` | Send a user message, get assistant reply |
| `POST` | `/check-eligibility` | Run eligibility check for a session profile |
| `GET` | `/profile/{session_id}` | Load profile (auto-creates if new session) |
| `PUT` | `/profile/{session_id}` | Update one or more profile fields |
| `GET` | `/chat-history/{session_id}` | Load saved chat messages |
| `GET` | `/bookmarks/{session_id}` | List bookmarked schemes |
| `POST` | `/bookmarks/{session_id}` | Save a bookmark |
| `DELETE` | `/bookmarks/{session_id}/{scheme_id}` | Remove a bookmark |
| `POST` | `/scrape` | Start scraping pipeline (requires `x-admin-token` header) |

## Scraping and Embeddings

Run the scraper via the protected endpoint:

```bash
curl -X POST http://127.0.0.1:8000/scrape \
  -H "x-admin-token: YOUR_ADMIN_TOKEN"
```

Or run it directly:

```bash
python myscheme_scraper.py   # Scrapes schemes from myscheme.gov.in via SerpAPI
python embedder.py           # Generates and stores embeddings for all un-embedded schemes
```

The scraper uses SerpAPI to discover scheme URLs and then applies a 4-strategy extraction pipeline to populate each scheme's `description`, `benefits`, `application_url`, and `youtube_url` fields in Supabase.

## Troubleshooting

| Problem | Solution |
|---------|----------|
| `[AI Offline]` in chat | Open LM Studio → Server tab → click Start Server |
| `[AI Error]` empty response | In LM Studio model settings, set Context Length ≥ 8192. Model needs room to think. |
| Chat is slow | Qwen3 thinks before responding (30–90s is normal). Enable GPU offload in LM Studio for speed. |
| CORS error in browser | The backend is not running. Start `uvicorn main:app ...` first. |
| `503` on eligibility check | Run the full `schema.sql` in Supabase SQL editor. |
| No schemes appear | Run `python embedder.py` to generate embeddings, then retry. |
| No YouTube video on cards | SerpAPI key may be exhausted or the scheme has no video indexed. |
| Voice features fail | Use Chrome or Edge, grant microphone permission. |
| No deadline reminder | Bookmark must include a valid ISO date deadline. Browser must allow notifications. |

## Production Considerations

- Replace the browser-generated session ID with a signed server-side session or access token.
- Add authentication and authorization to every profile, history, bookmark, and scrape route.
- Use HTTPS and a secrets manager (not `.env` files).
- Add a web-push service worker and background scheduler if notifications must work while the browser is closed.
- Restrict CORS origins in `main.py` to your production domain.
- Use a production ASGI server (Gunicorn + Uvicorn workers) and monitor Supabase rate limits.
- Host the LM Studio model on a GPU server or replace it with a hosted API (OpenAI, Gemini, etc.) for production scale.
